# 模型复现工程契约

## 边界

每个第三方模型均放在 `reproductions/<model-key>/` 下管理。只有在来源、许可证和版本已核验后，才将官方仓库以 Git submodule 的形式固定在该模型的 `upstream/` 目录中。

项目不将官方模型源码复制进 `src/`，也不在上游工作树中进行未记录的修改。

## 职责

~~~text
upstream/   固定提交版本的官方源码
adapters/   项目规范样本／预测结果与官方模型接口之间的适配层
patches/    没有适配器或配置方案时的最小化、可说明兼容性修改
reference/  证明固定上游版本和环境能复现预期行为的小型版本化证据
tests/      模型专用的导入、适配器、回归和单批次测试
~~~

推荐的处理优先级为：

~~~text
适配器
>
配置覆盖
>
环境兼容
>
上游补丁
~~~

## 提升至稳定框架

只有已经验证、且与单一模型无关的能力，才能提升到 `src/`。未来可能包括规范数据语义、产物读写和共享评估；第三方网络结构或采样器仍应留在其复现目录，除非另有明确且单独记录的自维护理由。
